ADMIN · SUPABASE SETUP

Connect your clinic's content.

This static website uses Supabase for shared copy, administrator sign-in, and image uploads. Connect your own project to enable shared edits.

1. Create the tables and image bucket

Open your Supabase project's SQL Editor, download and run the schema. It enables row-level security and makes website copy readable to visitors while reserving changes for authorised admins.

Download the SQL schema

2. Create and authorise the first admin

  1. In Authentication → Users, create an email/password user.
  2. Copy that user's UUID from the users list.
  3. In SQL Editor, run insert into public.admin_users (user_id) values ('YOUR-USER-UUID') on conflict (user_id) do nothing;

3. Configure public Supabase settings

Set these browser-safe build values, then rebuild and redeploy the static site:

VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY

Find them in Project Settings → API. Use only the public anon/publishable key; never place a service_role key in the website. Supabase row-level security protects edits.

4. Sign in and edit

Open /admin, sign in with the authorised account, and save content changes. The first save creates shared site copy. Only admins can upload to the public site-media bucket.

Before publishing

Phone, email, address, opening hours, and the map link start blank. Add real clinic details in the admin panel. Sample patient stories start hidden; use only verified copy you have permission to share. Privacy and terms links appear only after their destinations are configured. If moving to another static host, replace the initial photo URLs with images uploaded to your Supabase bucket.
